# Shadowing practice

Тренажёр шэдоуинга: студент слушает фразу из лекции, повторяет её и получает разбор по четырём линиям – мелодия (интонация), звуки, ритм, ударение – с подсветкой каждого слова. Всё работает в браузере, записи никуда не отправляются.

## Как это устроено

| Что проверяется | Чем | Как |
|---|---|---|
| Правильные ли слова | Whisper base.en (Transformers.js) | Распознанный текст выравнивается с целевой фразой по словам: пропуски, замены, лишние слова |
| Качество произношения | wav2vec2-base-960h (CTC, без языковой модели) | Принудительное выравнивание целевой фразы по буквам (алгоритм Витерби, как `torchaudio.forced_align`). Для каждого слова – уверенность модели в его звуках, откалиброванная по диктору: если диктор даёт 0,9, а студент 0,4, слово помечается. Плюс «что услышала модель» по звукам, без подсказки словаря |
| Интонация | Собственный трекер YIN (F0 каждые 10 мс) | Высота тона переводится в полутоны относительно средней высоты своего голоса (мужской и женский голос сравнимы). Запись студента растягивается на временную ось диктора по границам слов, и кривые сравниваются точка в точку: среднее отклонение в полутонах, форма, ядерный тон (fall, rise, fall-rise, rise-fall), движение тона на каждом слове, диапазон, слово с самым высоким тоном |
| Ритм | Границы слов из выравнивания | Темп, относительная длина каждого слова, совпадение пауз |
| Ударение | Энергия + высота тона | Какое слово выделено сильнее всего и где пик внутри длинных слов |

Итоговый балл: мелодия 40 %, звуки 30 %, ритм 15 %, ударение 15 %. Если мелодия заметно отличается, итог не может быть выше оценки мелодии больше чем на 20 баллов. Если не хватает слов, итог ограничен 45.

Почему старая версия «плохо считывала»: она сравнивала записи целиком вместе с тишиной в начале и конце, растягивала их равномерно, а Whisper сам по себе «додумывает» ожидаемые слова. Теперь тишина обрезается, сравнение идёт по словам, а произношение оценивает акустическая модель без языковой.

## Тренировка

На странице четыре шага, они идут по порядку:

1. **Melody** – студент мычит мелодию на «м-м» или «да-да». Оценивается только интонация и темп; звуки не мешают.
2. **Shadow slowly** – диктор звучит на скорости 0,75, студент говорит одновременно с ним (в наушниках). Темп сравнивается с замедленной записью.
3. **Shadow** – то же на обычной скорости.
4. **On your own** – студент говорит сам, без диктора; полная оценка.

Шаг считается пройденным при 80 баллах; лучший результат по каждому шагу виден на кнопке шага и хранится в браузере студента.

Во время записи голос студента рисуется вживую оранжевой линией поверх синей линии диктора. Кнопка «Loop» повторяет по кругу конец фразы с ядерным тоном или слово, выбранное в мелодии или в таблице.

## Звуки в МФА

Кнопка «Check sounds in IPA» загружает фонемную модель (wav2vec2-lv-60-espeak-cv-ft, около 330 МБ, один раз) и сравнивает звуки студента со звуками диктора по словам. В таблице появляется колонка с транскрипцией диктора и студента, различия подчёркнуты. Программа отдельно называет типичные отклонения от RP: /r/ после гласной, «американское» t между гласными, замену /θ ð/, лишнюю гласную в конце слова, пропуск конечного согласного, путаницу l/r и v/w, другую гласную.

После первой загрузки в этом браузере проверка запускается сама после каждой записи. Чтобы модель загружалась у всех сразу, поставьте в `data/settings.json` значение `"phonemes": "auto"`.

Модель обучена на многоязычных данных с транскрипцией eSpeak, поэтому отдельные символы могут отличаться от британской словарной транскрипции. Сравнение идёт со звуками самого диктора, так что это не мешает найти расхождения, но подсказку по отдельному звуку стоит проверять на слух.

## Структура

```
index.html               страница
assets/                  звуки: одна папка на лекцию
  ben-crystal-original-pronunciation/
    lecture.json         название лекции, исправления текста
    full/                полная аудиозапись лекции (один или несколько файлов)
    01 What was that.mp3 имя файла = текст фразы
data/lectures.json       список фраз, собирается автоматически из assets/
data/settings.json       модели, строгость, заголовок
tools/build_index.py     сборщик списка фраз (Python)
.github/workflows/       автосборка и публикация на GitHub Pages
css/style.css            оформление (корпоративные цвета)
js/                      логика страницы, анализ звука, модели (phonemes.js – сравнение в МФА)
tests/run-tests.mjs      тесты на синтетических сигналах (npm test)
```

## Публикация на GitHub Pages

1. Загрузите содержимое папки в репозиторий `Oletol/shadow`.
2. Settings → Pages → Build and deployment → Source: **GitHub Actions** (один раз).
3. После каждой загрузки GitHub сам собирает список фраз из `assets/`, сохраняет его в `data/lectures.json`, проверяет код и публикует сайт. Ход работы виден во вкладке Actions, обычно 1–2 минуты.
4. Адрес страницы: `https://oletol.github.io/shadow/`.

Открывать `index.html` двойным щелчком нельзя: браузер не даст загрузить список фраз и запустить модели. Для проверки на компьютере: `python3 tools/build_index.py`, затем `python3 -m http.server 8000` в папке проекта и адрес `http://localhost:8000`.

## Как добавить фразы и лекции

**Новая фраза.** Положите mp3 в папку лекции. Имя файла – это текст, который должен сказать студент:

```
assets/ben-crystal-original-pronunciation/18 It was a revelation.mp3
```

- Число в начале задаёт порядок в списке и на экран не выводится. Можно без него, тогда порядок по алфавиту.
- Текст в имени должен совпадать с тем, что звучит, слово в слово: по нему строится выравнивание.
- Знаки препинания не обязательны, анализ их не учитывает. Если нужен знак, который нельзя поставить в имени файла (например, `?`), допишите его в `lecture.json` в разделе `"texts"`.
- Цифры можно писать словами или числом (40 превратится в forty).
- Большие и маленькие буквы в именах важны для GitHub: не переименовывайте файл только регистром.

**Новая лекция.** Создайте папку в `assets/` латиницей без пробелов, например `assets/david-crystal-shakespeare/`, положите туда mp3 и, если нужно, `lecture.json`:

```json
{
  "title": "David Crystal on Shakespeare",
  "texts": { "01 What was that.mp3": "What was that?" }
}
```

Все поля необязательны. Без `title` название берётся из имени папки. Когда лекций больше одной, над списком фраз появляется выбор лекции.

**Полная аудиолекция.** Положите запись целиком в подпапку `full` внутри папки лекции:

```
assets/ben-crystal-original-pronunciation/full/Ben Crystal - Original Pronunciation.mp3
```

Если лекция длинная, её можно разделить на части: `1 Part one.mp3`, `2 Part two.mp3`. Имя файла показывается студенту как название части, число в начале задаёт порядок. На странице появится блок «Listen to the full lecture» с плеером; браузер запоминает, где студент остановился. Пока звучит лекция, фраза не играет, и наоборот.

Ограничения GitHub: один файл – не больше 100 МБ, весь сайт – до 1 ГБ. Для речи хватает mp3 моно 64 кбит/с: это около 0,5 МБ на минуту, то есть 40-минутная лекция займёт примерно 20 МБ.

**Проверка соответствия текста и звука.** Если в `data/settings.json` поставить `"showReferenceCheck": true`, под мелодией будет появляться строка с тем, что распознаватель слышит в записи диктора, когда это расходится с текстом. По умолчанию выключено.

## Встраивание в Moodle

Через ресурс «Страница» или «Пояснение» в режиме HTML:

```html
<iframe src="https://oletol.github.io/shadow/" width="100%" height="1400"
        allow="microphone; autoplay; fullscreen" style="border:0"></iframe>
```

Атрибут `allow="microphone"` обязателен, иначе запись внутри Moodle не заработает.

**Одна лекция на странице.** Чтобы студенты видели фразы только одной лекции, добавьте к адресу имя её папки:

```
https://oletol.github.io/shadow/?lecture=ben-crystal-original-pronunciation
```

С таким адресом выбор лекции скрыт, в списке только фразы из этой папки. Так удобно делать отдельную страницу Moodle на каждую лекцию. Без параметра студент видит поле «Lecture» и сам выбирает лекцию, а список фраз меняется под неё.

## Строгость

`"strictness"` в `data/settings.json` – значение по умолчанию: `lenient`, `standard`, `strict`. Студент может переключить её внизу страницы. При `strict` отклонение мелодии в 2 полутона уже даёт около половины баллов; это ближе к требованию «точно как у диктора», но для начинающих может быть слишком жёстко.

## Модели

При первом запуске браузер скачивает около 230 МБ (wav2vec2 – 95 МБ, Whisper base.en – около 136 МБ) и потом хранит их в кэше. Фонемная модель для МФА (около 330 МБ) загружается отдельно, по кнопке. Если нужно легче, замените `"recognition"` на `"Xenova/whisper-tiny.en"`. Если huggingface.co медленно открывается, в поле `"host"` можно указать зеркало, например `"https://hf-mirror.com/"`.

Пока модели скачиваются или если они недоступны, интонация и темп всё равно сравниваются, а по словам результатов не будет.

## Если проект лежит на внешнем диске

macOS создаёт на внешних дисках служебные файлы с именами `._…`. Они уже исключены через `.gitignore`, но могут появляться внутри `.git` и вызывать сообщения `non-monotonic index …/._pack…`. Это не мешает отправке; убрать их можно командой в папке проекта:

```bash
find . -name '._*' -delete
```

Проще всего держать проект на внутреннем диске Mac: тогда этих файлов не будет совсем.

## Ограничения

Оценка автоматическая и приблизительная. Модель произношения обучена на носителях американского и британского английского и оценивает буквы, а не фонемы, поэтому её вердикт по отдельному звуку – подсказка, а не диагноз. Для записи нужны HTTPS и тихое помещение; при режиме «Play the speaker while I record» лучше надеть наушники.
